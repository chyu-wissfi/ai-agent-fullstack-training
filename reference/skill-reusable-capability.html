1. 五个对象：谁来做、怎样做、做什么动作

对象职责不能推出
Tool读、搜、运行等具体动作知道完整审查方法
Prompt表达本次目标、规则与限制天然拥有发现、加载与版本机制
Skill保存稳定方法、材料、边界与验收自动执行、自动创建会话或扩权
Agent按当前观察选择方法并处理结果每次选择稳定正确
Subagent独立执行受委托子任务必须使用 Skill
主 Agent → 任务契约委托 Subagent
              ├─ 当前目标 / 路径 / 规则 / 权限
              └─ 加载 Skill 方法包
                    └─ 通过受治理 Tool 获取证据

2. 能力包：稳定方法与当前现场分开

.pi/skills/order-list-review/
├── SKILL.md                 # name / description / 方法 / 边界 / 验收
├── references/...           # 报告模板与按需材料
└── scripts/...              # 确定性检查，先独立验证接口
写入 Skill每次任务重新提供
确认入口、核对规则、分项检查、保留证据当前源码与测试入口、代码版本
静态与运行分开、失败如实报告当前业务规则及权威来源
报告字段与未知项要求允许动作、预算、输出格式
  • description 帮助选择；正文指导执行；模板填满不等于事实正确。
  • 业务路径按项目根目录；Skill 的 references/scripts 按 baseDir。
  • 「检查查询次数」是方法；「本项目最多 2 次」是本次规则。
  • metadata.version 是声明，不自动形成发布或实际生效证明。

3. 两种加载入口与三种事实状态

入口谁决定读取正文正文怎样进入模型输入主要证据
显式 /skill:name用户指定，宿主展开本轮展开输入实际请求、诊断；可无 read 记录
自动选择模型按目录判断文件读取工具结果干净会话 + 目标正文读取 Trace
磁盘读取（可能读全文解析）
  ≠ 程序对象保存全文
  ≠ 本轮模型请求包含全文

目录：name / description / location
正文：显式展开 或 自动读取
材料：按当前步骤继续读取；全部仍计输入预算
  • 先显式测通加载，再用干净会话测自动选择；旧正文会污染自动选择判断。
  • 渐进披露减少无关输入，也增加漏选、漏读与多层定位失败。
  • 目录过长可宿主筛选或检索，但要评测漏选、误选与实际成本。

4. 三层权限：方法文字不是授权

层负责快速检查
Skill / Prompt方法、范围与边界提醒是否把静态/运行、建议/修改分开
宿主与工具治理对象、动作、身份、批准、路径、命令、预算handler 前是否真实检查并留审计
Sandbox进程实际可访问的文件、网络与资源挂载、用户、网络与资源限制是否有效
  • 源码注释、工具输出和参考资料里的「允许」仍是材料数据。
  • 允许一个脚本 ≠ 允许安装、修改、外发或连接生产。
  • disable-model-invocation 只控制自动目录可见性，不是 ACL。
  • 本地/远程不是风险判据；看对象、动作与影响。

5. 四类任务 × 三道验收门

类型预期主要证据
正例该选时选中，逐项执行并取证目标正文 + 必要工具 + 正确报告
负例不该选时不误用无目标加载，任务仍正确完成
缺输入查权威规则，仍缺则保留未知缺什么、影响哪些检查
执行失败如实受阻，不伪造、不扩权错误、退出码、未完成范围
选对：显式看展开输入；自动看规范化目标路径 + 正文/指纹
做对：当前规则与源码是否读取；必要动作是否实际成功
说对：结论不超过证据；静态 / 运行 / 未知分开

每类用干净会话，保存任务、配置、版本、Trace 和报告。进程 exited、任务 completed、业务 pass 分开。无/有 Skill 对照要固定模型、项目、任务、权限和预算，比较发现、遗漏、误报、耗时与输入量，不看报告长度。

6. 五步提炼法

  1. 找反复出现、易漏规则、需统一输出或共享工具的任务。
  2. 稳定方法写入 Skill；当前路径、规则、版本与权限由任务提供。
  3. 把提醒写成条件 → 动作 → 证据 → 判断。
  4. 确定事实交给脚本，报告组织交给模板；区分业务失败与执行错误。
  5. 漏选改描述/目录，漏做改步骤，夸大改证据边界；重跑四类与旧能力。
性能：发现循环逐单查询 → 记录查询方式 → 允许时统计 SELECT → 与当前上限比较。
幂等：同一业务编号与参数重复提交 → 核对最终状态、有效记录数与响应契约。

7. Skills-as-Code：版本闭环

领域 Owner / maintainers
  → PR + Review
  → CI：正例 / 负例 / 缺输入 / 执行失败
  → 确定版本发布并接真实入口
  → 运行记录：实际版本或包指纹 + 实际请求 + Trace + 结果
  → 对照、回归、失败回流

文件更新 ≠ 旧会话更新 ≠ 平台 worker 加载 ≠ 效果更好。包指纹证明内容，不证明评审、权限、加载与业务收益。先用种子团队验证高价值痛点，再推广。

8. 当前课程代码的证明边界

  • setup_demo.py 生成 v1/v2 简化 SKILL.md 与 output.md；没有笔记示例的 check_orders.py，也不自动安装到项目 .pi/skills。
  • skill_manifest.py 哈希整包并拒绝符号链接；pi_runner.py 只记录 SKILL.md 哈希，项目 snapshot 只覆盖 app/tests/docs。
  • probe_orders.py 上限固定 <=2，不读 docs；grader 也是课程固定规则，不是通用语义 Judge。
  • read_skill_paths 只认已完成 read 且路径含 SKILL.md：显式/bash/pending 会漏，其他 Skill 会误算目标命中。
  • 历史 _smoke 的正例/缺输入均漏选、task_success=null；不是本机 live 结果，exited 也不等于任务通过。
  • 固定 pi 源码只读核对，真实 pi 与模型运行本机未验证。

9. 两分钟复述骨架

五个对象 → 稳定方法与当前现场 → 元数据/正文/材料 → 先显式后干净会话自动选择 → 磁盘/对象/模型输入三状态与预算 → Skill、Runtime、Sandbox 三层边界 → 正/负/缺输入/失败 × 选对/做对/说对 → 五步提炼 → Owner/PR/CI/发布/运行指纹/回归。
