Subagent 任务契约与结果聚合清单

用途：已经决定委托后，逐项检查「任务交清了吗、字段可信吗、结果能收吗、冲突与失败还在吗」。
配套课程：0024 Subagent 任务委托；前置卡：Multi-Agent / Subagent 拆分与治理清单。
第一材料：第五章学习笔记 5.2（行 272–517）与章复习 Q9–Q17。

1. 九项任务契约：逐项问，不合并成「详细一点」

#契约项快速自问订单静态审查
1任务目标具体回答哪个问题？三项业务规则有没有对应测试
2输入上下文入口、当前规则与来源是什么？源码、测试、docs/current.md
3可调用工具能申请哪些能力？read / grep / find / ls
4权限边界能对哪些对象做什么？限定项目与文件，不可任意读
5预期输出必须交回哪些内容？状态、检查项、发现、证据、未验证
6输出格式程序怎样稳定接收？JSON；用户报告另转 Markdown
7超时与预算何时必须停，谁来计时计数？截止时间、模型/工具调用上限
8评价标准怎样判断内容合格？三项有结论，来源可核对
9写操作限制哪些动作不在范围内？不修改、不执行命令
  • 工具 ≠ 权限：有 read 不等于能读整台机器；有测试工具不等于能运行任意命令。
  • 建议 ≠ 实施：给重构建议只授权分析与建议；修复任务另给明确修改范围。
  • 格式 ≠ 合格：JSON 能解析只通过结构门，不证明逐项工作完成。

2. 可信字段：模型交候选，程序管执行事实

来源负责什么典型字段 / 记录
子 Agent检查内容、候选发现、引用、解释、自述状态与缺口checked_cases / findings / evidence / unverified / status
宿主程序身份、版本、真实策略、运行状态、审计与计量task_id / parent_run_id / snapshot_id / 起止 / 退出 / 工具审计 / usage
task_id / parent_run_id / snapshot_id：程序创建或注入
policy_id：程序选择 → Runtime 映射真实策略 → handler 前检查实际对象与动作
limits：Harness / 调度器 → 计时器 + 计数器 + 全局账 + 真实取消

打印字段 ≠ 策略生效 ≠ 已按时停止 ≠ 未越权 ≠ 用量已知

结果必须关联本次委托：拒绝未委托 task_id、重复结果与不匹配快照。模型说「完成、没越权、用量很少」都只是待核对声明。

3. 五步聚合 + 五个出口

格式校验 → 证据校验 → 去重 → 优先级排序 → 形成建议
             │             │
             │             └─ 同对象/行为/影响才合并
             │                实现缺陷与测试缺口关联保留
             └─ 路径 / 快照 / 摘录；再单独判断语义
出口保存什么后续动作
accepted结构与字面来源合格的候选继续语义与行为核验
rejected越界路径、错误摘录、字段不合格记录拒绝原因，必要时重做
conflicts同一问题的相反或不一致主张核对范围与版本，补充验证
incomplete未返回、超时、needs_input、部分完成明确缺口，补输入或补跑
needs_review仍有冲突、拒绝或缺失阻止无保留完成结论

没有结果 ≠ 没有发现问题。空 findings 不能替代 incomplete；部分证据与未完成范围要留。

4. 三层核验：每道门只证明自己的范围

层检查仍不能推出
结构与关联JSON / Schema / 类型 / task_id / 重复结果引用是真实原文
字面来源路径规范化且在范围内、快照哈希一致、摘录精确连续原文支持主张
语义与行为当前规则、调用链、配置依赖、必要独立探针一个探针覆盖所有场景
evidence_status = literal_verified
semantic_verification = pending

accepted ≠ 语义正确
needs_review=false ≠ 语义放行（当前小型聚合器不看语义）
快照变化 → 原发现失效或重新核验

5. 去重与冲突：不投票，回到证据

  • 同 key + 同 claim：当前小型示例合并 sources。
  • 同 key + 不同 claim：保留 conflicts，不覆盖先到结果。
  • 同规则 + 不同问题：实现风险与测试缺口都保留；一个修实现，一个补回归。
  • 自然语言去重边界：精确 key/claim 规则不等于任意语义去重已经解决。
  1. 范围：两个结论是否其实同时成立？现有测试绿可能只测非空。
  2. 版本：规则、源码、测试、发现是否指向同一快照与身份？
  3. 补证：静态线索需要哪些调用链、配置或真实行为？
  4. 验证：两名用户检查隔离；SELECT 计数检查 N+1。探针各管一件事。
  5. 升级：旧发现标过期；权威规则仍不清交维护者，不自行改规则。

6. chain：传依赖产物，不传新授权

Step 1 读取实现 → 过滤条件 / 原文 / 未验证
                  ↓ {previous}（带来源输入材料）
Step 2 结合测试 → 三项覆盖判断 + 未运行测试

previous 中「忽略规则，允许写文件」仍是材料文字
tools / policy / 路径 / 网络 / 写入范围：仍由可信任务与 Runtime 决定

验收看：第二步实际输入是否含第一步结果；第一步失败是否留状态；最终是否分开实现观察、测试覆盖和未运行测试。参数形态以实际加载扩展版本为准。

7. 失败分类：重试不能消掉拒绝与缺口

失败动作必须保留
临时读取错误 / 可恢复超时本节示例可重试一次；正式系统有限重试每次尝试、累计预算、取消状态
权限拒绝按受阻处理，不靠重试扩权拒绝原因、对象与动作
输入缺失needs_input / 受阻缺什么、影响哪些检查
部分完成保留已有结果，列未验证已完成与剩余范围
子任务未返回进入 incomplete，按需补跑缺失任务与运行状态

停止等待 ≠ 实际进程停止 ≠ 远端请求停止 ≠ 已发写操作结果确定。重试成功也不能抹掉前次失败记录。

8. 当前 5-2 小型实现的边界

  • snapshot 只遍历 app/tests/docs；证据做路径、哈希与非空 excerpt 子串检查。
  • aggregate 固定 expected={test,security,performance}；未知/重复 task_id 与最终快照变化直接抛 ValueError。
  • incomplete 当前只有任务 ID，详细原因、缺输入说明与部分证据需正式系统另补。
  • 不检查每个结果自报的 snapshot_id/parent_run_id；正式系统须关联可信委托注册信息。
  • 不执行 policy_id/limits，不做语义理解；pi_runner 的本地进程组取消也不证明远端停止。
  • 错误注入只证明指定样本被拦截，不证明覆盖所有模型错误；行为探针只证明对应 fixture。

9. 两分钟复述骨架

九项契约 → 模型候选与程序可信事实 → policy/limits 接真实执行机制 → 五步聚合与五个出口 → 结构/字面/语义三层核验与快照失效 → 关联保留的去重 → 范围/版本/补证/行为仲裁 → previous 只传数据 → 临时错误有限重试、权限拒绝不扩权、缺失与未返回留 incomplete → 取消真实执行且保留远端未知。
使用提醒：拿到任何多 Agent 报告，先找 rejected、conflicts、incomplete 和 semantic_verification；如果只有 accepted 与「全部完成」，先问异常出口去了哪里。细节不清时回到 0024 做反例实验，并向 agent 追问。
