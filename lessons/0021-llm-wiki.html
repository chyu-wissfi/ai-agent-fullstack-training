第一部分：精讲（先读，测验在后）

0. 开篇：RAG 已经能查资料，为什么还要 Wiki

新人问登录模块，往往要同时读规则、源码和测试指南，再整理出：有效期多少、到期怎样判断、实现在哪里、怎样验证。每次问都重新建立这些关系，重复工作就会增加（笔记行 1937–1939）。LLM Wiki 让模型根据原始资料生成、组织和维护知识页，把可复用的总结、关联和分析保存下来，并随着来源变化更新（行 1941）。

但保存后的页面会被重复使用，错误、过期和受限内容也可能重复传播（行 1945）。所以知识资产治理要回答四件事：结论有没有依据，来源变化能不能同步，冲突有没有隐藏，谁可以生成、发布和阅读（行 1947）。还要记住：LLM Wiki 是工作模式，不是装上就自动成立的系统——维护方式变了，版本、审核、来源与权限要求仍要由工程师规定，不能因为目录叫 Wiki 就认为它会自动保持最新（行 1951–1955）。

1. 分工定位：Wiki、RAG、Memory 各管什么

为什么有了 RAG 还要 Wiki？ RAG 每次都为「这一个问题」找证据，关系整理（规则↔实现↔验证）做完就丢；Wiki 把这份整理沉淀成可维护的资产，下次直接复用。不这样的事故：每个新人都让 Agent 重读一遍全部资料，重复开销之外，每次整理还可能得出互相矛盾的结论。取舍：Wiki 省了重复整理，但背上维护责任——页面会过期、会传播错误，所以才有后面整套治理。与 0019 同构：OKF 是 Agent 自己的经验记忆，Wiki 是团队知识资产，写入筛选、来源、失效三问完全一样，只是维护对象从「我的经验」变成「大家的知识」。

2. 最小结构：依据、草稿、发布内容和维护记录分开

为什么依据、草稿、发布必须分开放？ 混在一起的事故：模型「顺手修正」了原文错别字，从此所有结论的依据都被污染且无法察觉；未检查的草稿被当成现行规则引用。分开后每段有明确的修改规则：raw 只读（新来源新增快照，不覆盖）、staging 可推翻、wiki 按发布规则更新。快照的 schema.md 第 1 条就是「来源快照只读」，连看起来过时、重复、冲突的文件也不删。取舍：目录与登记变多，换来的是任何结论都能回到一份未被改动的原文。与 0019 OKF「index/log/概念分文件」同构，但多了 staging 这道发布闸口——因为 Wiki 页会被别人当依据用。

3. 知识页三问与五类表达

知识页至少回答三个问题：适用于哪里，结论是什么，依据在哪里（行 2000）。页头管理身份、版本、状态和来源；正文组织规则、实现与核对入口（行 2002）。正文引用了 app/auth.py，页头和依赖清单也要登记它，不能只登记部分来源（行 2017）——快照 lint 报告恰好抓到这个真实缺陷：login-session 页正文引用 11 个来源，登记只有 8 个。

为什么三问缺一不可？ 缺「适用于哪里」：支付会话的规则被当成登录规则；缺「结论是什么」：页面变成资料堆砌，读者还要自己整理；缺「依据在哪里」：结论无法核对，错了也不知道错在哪一步。五类表达混存的事故正是本章贯穿案例：PRD 提出退出登录，logout() 却仍抛 NotImplementedError——把「希望实现」写成「已经上线」（行 1957）。这与 0019 四性质（要求/事实/推断/证据）、0018 三阶段（建议/修改/验证）同构：先定性质与来源，再谈使用。快照 acceptance 的可信度抽查专门核对「全绿/通过」字样全部位于验收要求或否定语境，没有一处把要求写成结果。

4. 生成与发布分开：模型整理内容，程序管理发布

为什么提交前还要再查一次？ 生成需要时间，期间原文可能更新、身份可能撤权、别人可能改了同一页（行 2068）。草稿仍写「退出未实现」，开发者却已提交实现——按旧源码发布就是把过期结论广播出去。所以提交前再核来源哈希、权限和页面基线，变化就停止覆盖。这与第三章 Harness「模型建议、程序把关」、0018「拒绝必须回写」同构：模型输出永远是候选，落盘生效必须过程序闸口。快照的 prepublish 报告是现成现场：内容核对抓出 2 处伪引文、3 处遗漏否定词、2 处行数错误、1 处省略号章节引用——结构检查全过也拦不住这些，必须逐条读含义。另注意口径：本地复制文件不等于已实现事务或原子发布（行 2074），快照 log 自述「逐文件 cp，非事务性」。

5. 来源追踪与更新传播

「读过哪些文档」与「这句话由哪一段支持」不同（行 2082）：30 分钟引用有效期长度，到期无效引用到期边界，实现位置引用函数，测试入口引用测试指南。派生页沿「对比页 → 知识页 → 原文」追到底（行 2094）；问答归档先核对来源、范围和重复，结论直接回查原文，不把模型输出自动变成事实（行 2098–2104）。

为什么不能全局替换数字？ 「30」在库里至少有五种身份：v1 历史规则、当前源码常量、FAQ/CSV 未同步原文、历史故障与发布说明、续期用例描述。全局替换会把源码事实改成假的、把历史改成篡改的——必须能分别回答当前批准规则、当前源码行为与 v1 历史规则（行 2138）。为什么间接依赖也要找？logout-plan 没直接引用规则来源，但它依赖 token-lifecycle 的续期描述，漏掉它就会出现「规则 60、方案还按 30 等」的隐性过期。这与 0020「换 Embedding 须重建文档向量」同构：上游变了，所有下游派生物都要沿依赖找齐，只改源头等于没改。快照 log 还如实记录「无向量索引、无缓存层、未失效任何缓存（因不存在）」——未接入就标未接入，这本身就是验收点。

6. 60/30/90：三种地位，不是一场投票

为什么不能「三个值投票取多数」或「取最新」？ 90 分钟只是讨论建议，还没进入规则状态；30 分钟是实现现状与历史，不是竞争规则。投票或取最新会把未批准建议晋升成规则、把源码事实改成规则的应然值。巡检的正确动作是先分类再处置：重复核对同项目版本范围后合并（保留各来源与背景）、过期退出默认当前查询（保留历史用途）、冲突比较范围状态权威生效期。报告先列页面、问题、证据、影响与建议，不直接删除或合并（行 2166）；「本次未发现问题」不等于永久正确（行 2168）。这与 0019 冲突四问（先核范围再比来源）同构，也呼应 0020 Citation 的教训：字面相同的词可能方向相反，数字相同的值可能地位不同。

7. 权限边界：贯穿读取、生成、发布和使用

为什么总结不能扩大阅读范围？ 维护 Agent 同时读公开说明与内部安全设计，生成的综合页仍可能包含受限事实——改变表达方式不会消除信息限制（行 2174，复习 Q30）。不这样的事故：受限源码在源头 0600，讨论它的知识页却 0644 世界可读，索引成了受限内容的无限制广播面（access-review §1.4 的真实发现）。为什么提示词自律不算？即便模型 100% 遵守，任何绕过模型的直接文件读取（cat、cp、tar）都不受约束。所以原稿口径是：有可执行身份控制就分别用授权与未授权身份测试；没有就如实标未实现，列接入点和用例，不能伪造拒绝日志或假装切换身份（行 2190）。这与 0019「格式通过≠事实正确」、0016「状态≠结论只认审计」同构：声明不等于机制，机制要有真实拒绝证据。

8. 四维验收：检查什么，才敢比较收益

为什么「整理得好」不等于「检索得到」，更不等于「更准更便宜」？ 快照把知识库整理得来源齐全、分区清楚，但换一种问法就 0 命中——整理质量与可检索性是两件事，后者要靠同义词映射或接入检索层（0020 的术语扩展正是解法）。收益比较的口径与 0019 记忆策略、你的 benchmark 工作一致：固定同一问题集，统一指标，再查失败原因；未实际比较就不能宣布更准或更便宜。另外「本次未发现问题」不等于永久正确——快照全部检查是一次性人工执行，无自动回归、无 CI。把 Wiki 接入 RAG 后还要重新维护证据标注，不能沿用已变化的旧节点 ID（行 2203）。

9. 面试视角：两分钟主链 + 追问链

两分钟主链（不看稿讲清）：Wiki 维护知识、RAG 为本次问题找知识、Memory 召回经验，工作记忆管当前任务 → 最小结构 raw 只读/staging 草稿/wiki 发布 + schema/manifests/logs/reports → 知识页三问（适用哪里/结论/依据）+ 五类表达分开 → 生成发布分离：模型整理内容，程序管合法输入、三层检查与提交前复核 → 来源追踪到具体位置，派生页追到原文，问答归档不自动变事实 → 原文变化沿依赖传播到不动点，按含义改不全局替换数字，索引缓存未接入标未接入 → 60/30/90 三种地位不投票，重复过期冲突三分处理 → 权限贯穿五环节，字段与提示词不是鉴权，没有机制就如实标未实现 → 四维验收，未比较不宣布更准更便宜。

知识资产治理
├── 分工：Wiki 维护知识 / RAG 找知识 / Memory 召回经验 / 工作记忆管当前
├── 结构：raw 只读 → staging 草稿 → wiki 发布；schema + manifests + logs + reports
├── 页面：三问（范围/结论/依据）+ 五类表达；无回执不写测试通过
├── 发布：模型整理内容，程序管输入、检查、提交前复核（哈希/权限/基线）
├── 追踪：结论→证据具体位置；派生页→原文；问答归档先核对
├── 更新：新快照登记 → 直接+间接依赖到不动点 → 按含义改 → 索引缓存同步
├── 冲突：60 规则 / 30 实现与历史 / 90 建议，三种地位；重复过期冲突三分
├── 权限：读取-生成-发布-使用-撤权五环节；字段≠鉴权；未实现就标未实现
└── 验收：完整性/可信度/时效性/可检索性；未比较不宣布收益

面试官追问链：

  • 「为什么不直接让 RAG 每次现查，省掉维护？」→ 关系整理反复重做是重复开销，且每次整理可能互相矛盾；Wiki 沉淀复用，代价是维护责任——所以治理链才是工程重点。
  • 「模型总结的页面凭什么可信？」→ 结论到证据具体位置映射 + 发布前三层检查 + 提交前复核哈希权限基线；prepublish 真实抓出伪引文与遗漏否定词，结构通过拦不住含义错误。
  • 「规则从 30 改 60，你怎么更新知识库？」→ 新快照登记替代关系，沿 sources_used 找直接依赖、沿 depends_on 反向传播到不动点；按含义改，源码 30、历史 30、未同步原文 30 分别保留标注；索引缓存同步，未接入标未接入。
  • 「受限资料总结后能公开吗？」→ 不能自动公开：总结仍含受限事实，可见范围由可信程序按来源权限确定；公开用公开来源或脱敏审批；提示词自律不算隔离，要有多入口真实拒绝测试。
  • 「你们 Wiki 比直接检索好多少？」→ 未做固定问题集的对照就不报收益数字；可检索性实测换词 0 命中说明整理≠可检索；先说清测了什么、没测什么，再谈比较。

实验 ⑥：权限纸面设计 + /tmp 闸口模拟——设计练习，不是快照能力（选做，落地验收⑤）

  • 对照 access-review.md §3 的五个接入位置，在 /tmp 用标准库模拟「策略文件 + 读取闸口 + 依赖传播 + 撤权响应」（从仓库根目录执行；这是设计练习产物，快照本身没有任何可执行鉴权）：
    python3 - <<'EOF'
import json
from pathlib import Path
base = Path("course_code/week04/4-5/llm-wiki-demo-step9")
lab = Path("/tmp/wiki-access-lab"); lab.mkdir(exist_ok=True)
audit = lab/"audit.log"; audit.write_text("# 模拟闸口审计（设计练习产物，非快照能力）\n")
dep = json.loads((base/"staging/dependencies.json").read_text())

# 纸面策略：SRC-001(auth.py 含密钥) 仅 alice/bob 可读，其余来源公开
PUBLIC = {"alice", "bob", "carol"}
policy = {s["source_id"]: ({"alice","bob"} if s["source_id"]=="SRC-001" else set(PUBLIC))
          for p in dep["pages"] for s in p["sources_used"]}
def effective(propagate):
    vis = {p["publish_path"]: set.intersection(*[policy[s["source_id"]] for s in p["sources_used"]])
           for p in dep["pages"]}
    if propagate:
        edges = [(e["from"], e["to"]) for e in dep["page_graph"] if e["type"]=="depends_on"]
        while True:
            new = {f: vis[f] & vis[t] for f, t in edges}
            if all(new[f] == vis[f] for f in new): break
            vis.update(new)
    return vis
def read_artifact(path, who, vis):
    ok = who in vis.get(path, PUBLIC)
    with audit.open("a") as f: f.write(f"{who} read {path} -> {'ALLOW' if ok else 'DENY'}\n")
    return ok

vis_np, vis_p = effective(False), effective(True)
print("alice 读 login-session:", read_artifact("wiki/technical/login-session.md","alice",vis_p))
print("carol 读 login-session:", read_artifact("wiki/technical/login-session.md","carol",vis_p))
print("carol 读 session-types(不传播):", "carol" in vis_np["wiki/comparisons/session-types.md"], "← 危险信号")
print("carol 读 session-types(传播后):", "carol" in vis_p["wiki/comparisons/session-types.md"])
print("carol 索引可见页:", sum("carol" in v for v in vis_p.values()), "/ 5")
print("carol 导出闸口放行文件:", sum("carol" in v for v in vis_p.values()))
policy["SRC-001"] = {"alice"}   # 撤权：bob 失去 SRC-001
vis_r = effective(True)
print("撤权后 bob 可见页:", sum("bob" in v for v in vis_r.values()), "/ 5")
txt = (base/"wiki/technical/login-session.md").read_text()
print("绕过演示: carol 直接 open() 仍读到", len(txt), "字符 -> 闸口必须覆盖所有入口")
print("审计行:", len(audit.read_text().splitlines())-1, "条 ->", audit)
