1. 一条主线：LLM + Tool 不够之后，工程系统一层层补了什么

课程用五个阶段组织 Agent 的能力演进——这不是行业官方的「五代 Agent」定义，而是回答一个问题的教学框架：当最早的 LLM + Tool 不够以后，工程系统究竟一层一层补了什么？真实发展是交叉的，今天的成熟 Agent 同时拥有这五类能力。

阶段解决的问题一句话抓手
Prompt模型按什么角色、目标、约束行动岗位说明书 + 行为规范
Context本轮模型到底看到了什么信息模型能力 ≠ Agent 能力：Context 给错了，模型一样做错
Harness谁把模型、Context、Tool、运行策略装配起来这一次 Agent Run「带着什么」开始
LoopTool 结果回来之后怎么办、如何持续工作从「一次调用」升级为「可循环的运行过程」
Graph多个独立任务如何并行协作节点 + 真实数据依赖边；fake-edge test 判断该不该并行

三个最容易混的概念，边界这样划：Harness 管装配（选模型、加载 Prompt、发现 Tools、注入身份权限、启动 Loop、记录 Trace）；Tool Runtime 管执行（这一条 Tool Call 能不能执行、怎么执行、怎么失败、结果怎么回去）——它是 Harness 里的执行基础设施；Loop 管推进（结果怎样回 Context、下一步是否继续、何时结束）。

2. 最小 Agent Loop 的五个检查点（本课最重要的一张表）

最小 Loop 的代码很短，复杂的是后面不断加入的工程能力。真正要背下来的是这五个边界——每个检查点对应一类「AI 生成代码最常踩的坑」：

检查点守住的边界违反后的典型症状
① 模型只提出候选动作模型拿到 Context + Tool Schema，拿不到 handler；只能「请求调用」把 handler 直接暴露给模型，模型绕过权限自行执行
② Loop 判断继续还是结束终止条件在模型之外：max_turns、用户取消、预算、安全策略模型反复调用 A→B→A→B，永远不停
③ 所有 Tool Call 都进入 RuntimeLoop 只调度，Runtime 统一执行（注册表 + 查找 + 结构化结果）Loop 长成巨型 if/else，权限、超时、审计无处安放
④ Tool Result 必须写回 Context结果是新的 Observation，不是最终答案；保留 tool_call_id模型不知道刚才执行了什么，重复调用或答非所问
⑤ Loop 必须有确定性的运行上限系统何时停止由工程系统用确定性规则控制把「什么时候停」交给模型，预算烧穿

贯穿整门课的一条原则就藏在这里：LLM 负责不确定性决策，工程系统负责确定性边界。后面的 Runtime、Harness、State Machine、Sandbox、Graph 都在落实这句话。

工作对应：你在 OpenViking 做的 VikingDB / local 双后端检索对比，落点就在检查点③——上层协议不变，执行基础设施在 Adapter/后端层切换。这是「能迁移」标准的日常练习。

3. 1-2 的主链：模型调用只是运行链中的一环

任务目标与可信上下文
        ↓
Model Adapter 组装请求
        ↓
模型返回候选输出 / 结构化事件
        ↓
Schema 与业务规则校验
        ↓
稳定的 ModelResult 或错误语义
        ↓
Agent Loop / Harness 决定下一步

这条主链的要点：模型输出只是候选内容，必须经 Adapter、Schema 校验和失败策略，变成可信、可追踪、可恢复的 ModelResult，才能交给 Loop。JSON 只说明「像数据」，不说明「业务已经正确」。

4. 失败五阶段速查（每阶段策略不同，不能一个 retry 包打天下）

阶段典型故障策略
请求前认证失败、参数非法必然失败：立即终止、报警修配置（校验前置）
传输中超时、临时网络错误有限重试：指数退避 + jitter
服务端限流、过载尊重 Retry-After，退避或切换只读备用（防放大雪崩）
生成后拒答、截断终止或人工；截断先修预算，不是格式错误
解析后Schema / 业务校验失败一次纠错重试，仍失败则结构化返回

两条配套纪律：重试只包裹无副作用的模型请求——下游写操作（下单、建单）要用另一套幂等、审批策略，混成一个 retry() 会制造重复下单事故；失败必须结构化——ModelResult（ok / text / error_code / retryable / trace_id）让 Loop 不解析堆栈就能判断下一步。

5. 参数与预算：三件套速查

  • temperature：采样随机性。抽取、分类、工具参数建议低波动；不是「更聪明」按钮。
  • top_p：候选词概率质量范围。通常与 temperature 二选一做主要调节，不要同时盲调。
  • max_tokens：输出预算。控制成本与截断风险；设太小会把截断误判成格式错误。
  • 三份预算：系统指令与可信规则 / 当前任务证据 / 模型输出空间——Context Window 是总预算不是免费记忆，历史消息不能无上限累积。
