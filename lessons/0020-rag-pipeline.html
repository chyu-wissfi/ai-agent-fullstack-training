第一部分：精讲（先读，测验在后）

0. 开篇：知识组织好了，为什么还要 RAG

0019 的 OKF 把少量高价值知识组织成目录树，「先读索引，再读相关概念」够用。但本项目资料有 12 份：规则文档、代码、历史故障与需求记录、PDF 版 PRD、CSV 状态矩阵、HTML 发布说明（corpus/）。资料一多，逐份读全文会撑爆预算，靠索引猜哪份相关又容易漏——需要按问题把相关证据找回来，再放进模型输入（笔记行 1217–1238）。这就是 RAG：检索增强生成，没有修改模型参数，只是外部资料进了本轮请求。

本节标题就是主线：「先找到证据，再检查回答」（行 1215）。两件事缺一不可：证据没找到，生成再流畅也是无依据；证据找到了，回答仍可能用错、编造或引用错编号。口径提醒：本节原稿演示使用 MiniMax embo-01 与本地 BGE，不能把其他小节的 DeepSeek 配置写成本节已运行配置（行 1240）。

1. 两阶段链路：离线准备与在线回答

为什么分离线在线两阶段，而不是「问一句查一句」？ 解析、分块、建库有成本，离线做一次、在线复用；更重要的是错误定位：离线环节丢掉的证据（表格拆散、否定词被清洗、分块切断条件），在线换任何检索模型都补不回来。事故形态：只调在线 top_k 与重排，gold 其实在分块时就丢了。这与 0017 同构——预算与压缩决定检索结果怎么进请求，装配不是免费搬运；也与 0018 划清边界——工作记忆是「这一次任务的当前状态」，检索证据是「本轮从外部资料取回的内容」，两者来源与证明力不同，不能混。

2. 最小闭环：检索、装配、生成校验是三个独立问题

最小闭环（笔记 二，行 1242–1345）：Document 是整份资料，Node 是带元数据的检索单元（行 1263）；Markdown 先用 MarkdownNodeParser 按标题切，再用 SentenceSplitter(chunk_size=384) 拆长小节——384 是分块器 Token 口径，不是 384 汉字，也不是整次请求大小（行 1275–1283）。Embedding 让「登出」与「退出登录」有机会匹配，但文档与查询必须走匹配的模型与处理方式，同为 1536 维不代表可比较（行 1292–1300）。

为什么「不看分数猜质量」？ 相似度分数只回答「语义相近」，不回答「正确证据在不在里面」。q_hard 三条候选分数都在 0.93 以上，判定也通过，但需求讨论记录里没有「改哪些文件」的完整答案，模型只能泛化。替代方案「按分数阈值宣布检索成功」的事故：高分噪声挤掉低分 gold。这与 0019「格式通过≠事实正确」、0018「工具正常返回≠业务验证通过」同构——每一层的「通过」只证明那一层的事。一致性检查也要认清边界：它是本项目代码的字面核对能力，方向反转、隐含条件它查不出来（实验④会现场演示）。

3. 数据准备：答案别在入库前丢失

数据准备五件事（笔记 三，行 1347–1443）：解析保留关系——表格按行保留记录、每个值带列名（「情况：恰好到期；期望：False」），不能把条件与结果拆成两段（行 1359–1377，复习 Q18）；清洗有红线——「不 / 仅 / 禁止 / 必须」这类决定含义的词不能删（行 1381）；分块同时看完整性与粒度——AST 分块保留函数/类等完整代码单元，但不说明业务请求经过哪些模块，调用链仍要追入口、调用方、配置与数据流（行 1402–1417，复习 Q19）；Overlap 缓解边界断裂也增加重复（行 1421）；Chunk Metadata 决定过滤与追溯能力——file_path、heading 让引用可反查、让范围过滤可行（行 1433）。

为什么数据准备是失败归因的前排嫌疑？ 因为它的错误静默：解析丢了对应关系、清洗删了否定词、分块切断了条件，入库照样成功、检索照样返回高分，只有回到原文对照才发现证据早已不在节点里。替代方案「先上检索技巧再回头补数据」的代价：在丢证据的语料上比较任何算法都没有意义。这与 0019「先组织再检索」同构——检索技术的上限由语料质量决定；验收第①条「正确规则真实存在于节点中」（行 1915）就是先查这一层，实验①用 gold 对照离线落地。

4. 检索：层次、RRF 与查询处理

先分清三个指标（行 1458–1476）：召回率＝每题找回 gold 比例再平均；命中率＝至少找到一处 gold 的题占比；完全命中＝所有标注证据都找到的题数。一题两处 gold 只找回一处：召回 0.5、命中是、完全命中否——三者可以同时成立，不能只看一个平均数。换 Embedding 要重建文档向量并核对索引配置，只改查询侧会让两边处于不同向量空间（行 1478–1490，复习 Q20）。层次要分清：BM25 是关键词相关性评分方法，Elasticsearch 是承载全文检索/过滤/聚合的系统（可用 BM25 评分），向量库负责向量存储与相似度检索（行 1512–1532，复习 Q21）；中文 BM25 要有一致分词（原稿用 jieba）。

对象确定之后再谈过滤：Metadata Filter 先确定对象再过滤（行 1573）；问题本身不清楚时走查询处理（行 1585–1623，复习 Q23）——对象不明（「会话多久过期」没说哪个服务）先结合项目上下文定范围，仍不确定就向用户澄清；对象明确但用词不匹配（「验证命令」vs 文档里的「测试入口」）用重写、分解、多路、术语扩展，改写后必须重新检索，原意不变。原稿 step3b：重写/分解/多路都停在 0.812 仍漏 q4，只有术语扩展把召回提到 0.938、命中率 1.0——q4 的 top1 没变，但 gold 进了候选（runs/step3b.txt）。

为什么两路分数不能直接相加，k 又不是 Top-K？ 余弦相似度集中在 0.8–0.95，BM25 可以是十几分，直接相加等于让 BM25 尺度支配结果。RRF 只看排名：每路第 r 名贡献 w/(k+r)，k=60 让头部名次差距被平滑（第 1 与第 2 只差约 1/61 vs 1/62），它是融合参数，与「最终留几条」无关（复习 Q22）。实验③会看到：k 从 60 改到 1 排序不变但分数差拉大；权重 70/30 能翻转 top1。取舍：混合检索多一路开销，不保证提升——step3 里 RRF 等权候选 3 反而低于 BM25 单路，配置要用固定题集比较出来，不是「混合更高级」。

5. 后处理：选好证据，再检查回答

Rerank 能改排序，不能补回候选之外的内容（行 1643–1654，复习 Q24）：q4 的 gold 在 20 条候选里排第 20，重排后前三仍没有它——这是召回遗漏，要回解析/分块/查询/检索，不是换更贵的重排模型。LLM 重排要看它实际收到什么：原稿每段只传前 220 字符，截断可能恰好切掉关键句（行 1658）；Cross Encoder 把问题与候选成对打分，分数是相关性不是正确概率（行 1676）。上下文压缩少给内容、也可能删掉证据（行 1702）；后处理要同时看质量与开销（行 1718）：runs/step4 里 A 检索直出 / B +Rerank / C +Rerank+压缩答案正确率都是 8/8，B 耗时 36.1→67.5s，C 输入 7656→5922 Token 但无依据实体从 2 回升到 3。

回答生成后，Citation 至少分三层检查（行 1739–1761，复习 Q25）：① 编号合法——引用对应本轮存在的证据；② 实体有依据——路径、数字、命令能在被引证据里找到；③ 结论受支持——证据真正证明整句话，包括否定、条件、版本与适用范围。前两层是代码可查的，第三层要人或更强检查器核对。校验失败以后怎么办？要定义发布行为（行 1765）：标记、拦截、重试还是转人工，不能「检查完了照样发」；事后发现错误不等于已阻止展示。

为什么「更复杂」「更短」不是有效证据？ step4 的 B 加了重排：答案验收没提高（8/8→8/8），耗时接近翻倍；C 再压缩：输入少约 23%，无依据实体却从 2 回升到 3——压缩可能恰好删掉支持结论的那句。替代方案「组件越多越专业」的事故：成本与延迟上去了，质量原地踏步甚至下降，还无法归因（多处同时变化）。这与 0017 的预算取舍、0019 的「策略是取舍不是测出的结果」同构：有效性只能来自固定条件下的比较。引用三层同理——编号合法是格式层，实体有依据是字面层，结论受支持才是业务层，每层的「通过」只证明那一层的事（0019 核心不变量在 RAG 里重演）。

6. 评估与失败归因：固定题集，找第一个断点

第五步用固定问题集按相同口径比较（笔记 六，行 1779–1890）：同样 9 份资料、30 个节点、8 道题，V0 最小闭环 → V1 检索优化 → V2 +Rerank → V3 +压缩。三个逐题案例值得背下来：q2——V1 只找到一处 gold，召回 0.5、答案关键词通过、引用却是「无可核对实体」，命中/召回/答案检查可以不一致（行 1808）；q4——V2/V3 写出了必备命令却没有 gold 指定小节，关键词通过不能替代依据（行 1820）；q6——命中常量来源、出现「1800」，仍判存在无依据实体：换算表达不等于源码事实（行 1835，复习 Q26）。汇总数字按检查器口径解释（行 1843）：答案检查是关键词验收不是全面正确率；「含无依据实体 2/8」是回答数占比不是幻觉率。Token、费用与计时必须对齐（行 1860）：输入省 27% 不等于总费用省 27%（后处理用量没计全）；V2/V3 都约 8.3 秒/题但计时范围不同，不能直接比；usage 缺失填 0 是待修正项，正式报告记录未知。

口径差（已逐行核对）：笔记与 runs/ 快照不是同一次运行。逐题检索数字一致（0.312/0.625/0.688/0.812/0.938 与 q2/q4/q6/q7 逐题行），但汇总数字漂移：无依据实体笔记 A4/B1/C3（行 1727）vs runs/step4 A3/B2/C3；V0 答案检查笔记 4/8（行 1847）vs runs/step5 5/8；V2 引用合格笔记 5/8（行 1848）vs runs 6/8；V3 输入节省笔记 2,308 Token/约 27%（行 1862）vs runs 7731−6032=1699/约 22%；Cross Encoder 耗时笔记 137.10s（行 1696）vs runs/step4c 96.73s。引用任何数字都要注明是哪次运行——这正是本课「口径意识」的现场教材。

为什么归因要「找第一个断点」而不是看最终答案？ 最终答案错可能是六层中任何一层丢的证据，直接调生成提示词可能修的是第 3 层的病。按顺序查、停在第一个失败环节，修完用原题复测——这与第三章 Harness 的失败归因沿 Trace 找第一个断点完全同构，也与你的 benchmark 口径意识同构：指标本身也要被检查（第 6 步：检查结果是否如实表达覆盖）。「生成失败为空」只说明这套规则未检出，不能推导「检索到了就一定答对」；八题都有答案，不能推断系统会拒答——所以无答案题要单独统计正确拒答与错误作答。

7. 面试视角：两分钟主链 + 追问链

两分钟主链（不看稿讲清）：RAG 是外部证据进输入、没改参数，分离线在线两阶段 → 数据准备五道工序（解析保留关系/清洗红线/分块完整性与粒度/Overlap/Metadata），答案别在入库前丢失 → 检索分层次（BM25 评分方法/ES 系统/向量库），指标分口径（召回率/命中率/完全命中），换 Embedding 重建文档向量 → 混合用 RRF 按排名融合，k=60 是平滑参数不是 Top-K，混合不保证提升 → 查询处理先分对象不明与用词不匹配，改写后必须重新检索 → 后处理四象限定位，重排补不回候选外证据，压缩可能删证据 → 引用三层检查（编号合法/实体有依据/结论受支持），校验失败要定义发布行为 → 固定题集同口径比较，Token 费用计时对齐，无答案题单独统计 → 失败沿六步找第一个丢证据环节，一次修一个再复测。

RAG 链路
├── 是什么：外部证据进输入（≠参数更新）；离线准备 + 在线回答
├── 数据准备：解析保留关系 / 清洗红线 / 分块完整性+粒度 / Overlap / Metadata
├── 检索：层次（BM25 方法 / ES 系统 / 向量库）；换模型重建文档向量
├── 融合：RRF 按排名，k=60 平滑参数 ≠ Top-K；混合不保证提升
├── 查询处理：对象不明→澄清；用词不匹配→扩展后重新检索
├── 后处理：重排补不回候选外；压缩可能删证据；质量与开销同看
├── 校验：编号合法 / 实体有依据 / 结论受支持；失败定义发布行为
├── 评估：固定题集同口径；Token/费用/计时对齐；无答案题单独统计
└── 归因：六步找第一个丢证据环节；一次修一个，原题复测

面试官追问链：

  • 「检索效果不好你怎么排查？」→ 不先调模型：按六步顺序查原文→分块→候选→请求→结论→检查器，停在第一个丢证据的环节；q4 排第 20 是召回/排序问题，换重排模型补不回候选外的 gold。
  • 「RRF 的 k=60 是什么意思？」→ 排名贡献 w/(k+rank) 的平滑参数，控制头部名次差距的衰减；不是返回 60 条，也不是每路取 60 条；最终留几条由 Top-K 决定。
  • 「加了重排和压缩，效果一定更好吗？」→ 不一定：原稿 step4 答案验收 8/8 不变、耗时近翻倍、压缩后无依据实体回升；有效性要固定题集同口径比较，组件增加不是提升证据。
  • 「引用检查通过就能发布吗？」→ 三层各管一段：编号合法是格式、实体有依据是字面、结论受支持才是业务；「不要修改测试」被答成「可以修改」字面检查查不出；校验失败还要有预定义的发布行为。
  • 「怎么证明系统不会编造？」→ 八题都有答案证明不了拒答能力；无答案题单独设计验收（正确说明资料不足）与统计（空 gold 不沿旧分母），usage 未知不填零。

实验 ③：纯标准库 RRF 复算——k=60 的语义与 Top-K 的区别（落地验收②⑤）

  • 先看真实实现的签名与核心行，再用标准库复算（从仓库根目录执行）：
    grep -n "k: int = 60\|k + rank\|top_k: int = 5" course_code/week04/4-4/rag/retrieve.py
python3 - <<'EOF'
def rrf(lists, top_k, k=60, weights=None):
    weights = weights or [1.0]*len(lists)
    fused = {}
    for w, results in zip(weights, lists):
        for rank, nid in enumerate(results, 1):
            fused[nid] = fused.get(nid, 0.0) + w/(k+rank)
    return sorted(fused.items(), key=lambda kv: kv[1], reverse=True)[:top_k]
vec = ["A","B","C","D"]; kw = ["B","C","A","E"]
fmt = lambda rs: " / ".join(f"{n} {s:.5f}" for n, s in rs)
print("等权 k=60 top3:", fmt(rrf([vec,kw], 3)))
print("70/30 加权 k=60 top3:", fmt(rrf([vec,kw], 3, weights=[0.7,0.3])))
print("等权 k=1  top3:", fmt(rrf([vec,kw], 3, k=1)))
print("k=60 top_k=3 条数:", len(rrf([vec,kw], 3)), "| top_k=60 条数:", len(rrf([vec,kw], 60)))
EOF
    先写预期：两路排名 vec=[A,B,C,D]、kw=[B,C,A,E]，等权融合谁第一？把向量路权重调到 70% 会怎样？k 从 60 改到 1 排序变吗？top_k=60 能返回 60 条吗？
    预期（本机实测）：真实实现 rag/retrieve.py 行 69–70 签名 rrf_fuse(..., top_k=5, k=60, weights=None)、行 85 fused[key] += weight/(k+rank)。等权 k=60 top3：B 0.03252 / A 0.03227 / C 0.03200（B 两路都靠前）；70/30 加权：A 0.01624 / B 0.01621 / C 0.01595——权重翻转 top1；k=1 顺序不变（B/A/C）但分数差拉大（0.83333/0.75000/0.58333）——k 是平滑参数，改变的是衰减不是条数；top_k=3 返回 3 条、top_k=60 只返回 5 条（两路并集只有 5 个节点）——k=60 与返回条数无关（复习 Q22 现场）。

import re
from pathlib import Path
import jieba
from rank_bm25 import BM25Okapi
base = Path("course_code/week04/4-4/corpus")
nodes = []
for p in sorted(base.rglob("*")):
    if not p.is_file() or p.name.startswith(".") or p.suffix not in {".py", ".md"}:
        continue
    t = p.read_text(encoding="utf-8")
    rel = str(p.relative_to(base))
    if p.suffix == ".py":
        nodes.append((rel, t))
    else:
        body = re.sub(r"\A---.*?---\s*", "", t, flags=re.S)
        for chunk in re.split(r"(?m)^(?=## )", body):
            if chunk.strip():
                nodes.append((rel, chunk))
tok = lambda t: [w for w in jieba.lcut(t.lower()) if w.strip()]
bm25 = BM25Okapi([tok(t) for _, t in nodes])
def show(tag, query):
    scores = bm25.get_scores(tok(query))
    top = sorted(range(len(nodes)), key=lambda i: scores[i], reverse=True)[:3]
    print(tag)
    for r, i in enumerate(top, 1):
        head = nodes[i][1].splitlines()[0][:40]
        print(f"  top{r} {nodes[i][0]} {scores[i]:.3f} | {head}")
show("q6 原问题", "SESSION_TTL_SECONDS 这个常量的值是多少？")
show("q4 原问题", "退出登录改完以后，用哪条命令验证？")
show("q4 术语扩展", "退出登录改完以后，用哪条命令验证？ 测试入口 python -m pytest")
print("节点数:", len(nodes))
