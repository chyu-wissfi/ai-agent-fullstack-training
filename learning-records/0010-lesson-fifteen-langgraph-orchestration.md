**Evidence**: 2026-11-16 生成 `lessons/0015-langgraph-agent-orchestration.html`，覆盖 Week03 3-6。材料以学生笔记 3.6 节（行 2583–3107）为第一来源，代码为 `course_code/week03/3-6/release_pipeline/` 与 `demos/01_minimal`–`06_visualize`。本机 `agentloop` 环境（Python 3.12 / LangGraph 1.2.17）实测：顶层 `pytest tests/ -q` 为 **7 passed**；六个 demo 逐目录运行分别为 **4 / 4 / 4 / 5 / 5 / 5 passed**；`python -m app demo L` 得到 `released`、`canary_cursor=3`、三次 SRE interrupt；`demo canary_fail` 得到 `rolled_back`、`rollback_count=2`、`canary_cursor=0`；M 级 `submit` 停在 `INT-1`，跨进程 `approve` 后推进到 `INT-3-canary_10`；在 `approval_m` 开头加 `print` 后 `submit` 与 `approve` 各打印一次，证明恢复会从头重跑节点；把 `approvals` 的 `add` 改成覆盖后 **2 failed, 5 passed**（M 级丢 tech_lead、H 级丢 tech_lead）。另发现两处材料与实现不一致：README §2 的 `--ticket` 写法与当前 `app.py` 的位置参数不符；固定 `ticket_id` 的 demo 复用旧 `checkpoints.sqlite` 时会从旧存档续跑，得到 `cursor=1` 却报 `released` 的误导结果。

**Diagnosis**: 0014 分数未报，用户直接进入 3-6，因此 Q1–Q3 按 0014 三条核心不变量（一个结果两个消费者、完成检查只认最新事实、恢复先核对现场）换形式重测，不假设已掌握。3-6 是 Week03 第一次切到 Python/LangGraph，风险有三：①把「LangGraph」当成 Agent 的默认答案，而不是按流程形状做取舍；②把 `interrupt()` 理解成「停在调用行」，从而在它之前放副作用；③把 `recursion_limit` 当成业务预算，导致正常业务收尾变成框架异常。另一个教学风险是照抄 README：CLI 写法与代码已经不一致，若不先读签名会直接报错。这些都必须用代码和实验证据讲，而不是只讲 API。

**教学决策**: 本课采用「业务流水线 → 图对象 → 逐层加机制 → 工程坑 → 何时不用」的主线，配 7 张 SVG：业务对象映射、完整发布图、三种 reducer、ToolNode 并行、interrupt 恢复时间线、修订/灰度双循环、选择决策树。why 统一落到取舍：显式图的可检查性 vs 装配成本；增量更新对并行/重放的收益 vs reducer 心智负担；`add_messages`/覆盖/`add` 三种字段语义；业务预算的正常终态 vs `recursion_limit` 的异常安全阀；sync 节点走线程池 vs `async def` 阻塞事件循环。测验 18 题 = 14 选择 + 4 简述（Q1–Q3 间隔重测 0014；Q4–Q14 覆盖 Trace/Checkpoint、节点定位、TypedDict、条件路由、ToolNode、reducer、interrupt、跨进程恢复、重新提交、业务预算、何时用；Q15–Q18 简述 interrupt 时间线、三种 reducer、两个循环预算、三个工程坑）。实验①–③离线可跑（基线、两个 demo、M/H 跨进程审批），④⑤为主动改造（print 证明重跑、reducer 改覆盖），⑥只读 Mermaid 与快照；所有预期先写再跑，命令给出 venv 与 `conda run -n agentloop` 两条路径并标注本机实测结果。

**Implications**: ①0016 项目三会组合 `project3/v2` 的 pi 循环与 `hitl/graph.py` 的 LangGraph 审批图，本课应作为「按职责切分」的铺垫：主体 Agent 用 Loop、审批服务用图，不追求整系统一张大图；②0016 测验前 3 题可重测本课三条不变量（interrupt 前无副作用、`thread_id` 不是权限、业务预算正常收尾），并继续用真实产物证明恢复只执行一次；③后续讲解 LangGraph 相关材料时，先核对 CLI 签名与固定 ticket/thread 的测试隔离，不照抄 README；④「材料与实现不一致时以代码和测试为准」已连续两课出现（0014 作业设计文档、0015 README CLI），可写成结课复盘的一条工程纪律。详细实验输出与命令见 NOTES「0015 生成记录」。
